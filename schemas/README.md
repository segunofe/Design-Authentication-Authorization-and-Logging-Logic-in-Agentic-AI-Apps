# API and Lambda Function Schemas

This directory contains OpenAPI specifications and Lambda function schemas for the SEC307 Agent Identity Management Workshop.

## Overview

These schemas are designed for use with **AgentCore Gateway** to enable AI agents to interact with the workshop's sales operations APIs through structured, validated interfaces.

## Schema Files

### OpenAPI Specifications (API Gateway Endpoints)

| File | Endpoint | Description |
|------|----------|-------------|
| `view-sales-api.json` | `GET /view-sales` | Views sales records with role-based authorization |
| `get-inventory-api.json` | `GET /inventory` | Queries inventory from supplier systems |
| `view-product-catalog-api.json` | `GET /products` | Views product catalog with filtering |
| `get-driver-api.json` | `GET /driver` | Retrieves driver information |
| `get-truck-api.json` | `GET /truck` | Retrieves truck information |
| `get-tos-lambda.json` | Lambda | Terms of Service Lambda function schema |

### Lambda Function Schemas (in `../other-schemas/`)

| File | Function | Description |
|------|----------|-------------|
| `view-sales-lambda.json` | `view-sales` | Lambda function schema with authorization context |
| `get-inventory-lambda.json` | `get-inventory` | Lambda function schema for inventory queries |
| `view-product-catalog-lambda.json` | `view-product-catalog` | Lambda function schema for product catalog |
| `get-driver-lambda.json` | `get-driver` | Lambda function schema for driver information |
| `get-truck-lambda.json` | `get-truck` | Lambda function schema for truck information |

## Deployment

### Automatic Deployment
Schemas are automatically uploaded to S3 during CloudFormation stack deployment via the `SchemaUploaderFunction` Lambda.

### Manual Upload
Use the provided script to upload schemas manually:

```bash
./upload-schemas.sh [workshop-prefix] [environment]
```

Example:
```bash
./upload-schemas.sh sec307-workshop dev
```

## S3 Bucket Structure

Schemas are stored in a private S3 bucket with IAM-based access:
- **Bucket Name**: `{WorkshopPrefix}-schemas-{AccountId}-{Region}`
- **Access**: Private bucket with presigned URL generation
- **CORS**: Enabled for cross-origin requests
- **Security**: No public access, uses Lambda-generated presigned URLs

## AgentCore Gateway Integration

### Target Configuration

Use presigned URLs generated by the Schema URL Generator Lambda function:

```bash
# Generate presigned URLs (valid for 1 hour)
./get-schema-urls.sh

# Or invoke Lambda directly
aws lambda invoke --function-name {schema-url-generator-function} --payload '{}' response.json
```

The response will contain presigned URLs like:
```
https://{bucket-name}.s3.amazonaws.com/record-sales-api.json?X-Amz-Algorithm=...
```

### MCP Tool Integration

The Lambda schemas provide detailed input/output specifications for Model Context Protocol (MCP) tool development:

1. **Input Validation**: Request body schemas with required fields and data types
2. **Output Contracts**: Response schemas for successful and error cases
3. **Authorization Context**: User role and team information for access control
4. **Environment Variables**: Required configuration for Lambda functions

## API Usage Examples

### View Product Catalog
```bash
# All products
curl https://api-gateway-url/products

# Filter by brand
curl https://api-gateway-url/products?brand=happyToys

# Filter by product name
curl https://api-gateway-url/products?product=Car

# Combined filters
curl https://api-gateway-url/products?brand=happyToys&product=RC
```

### Get Inventory
```bash
# All inventory
curl https://api-gateway-url/inventory

# Specific product
curl https://api-gateway-url/inventory?product_id=PROD001
```

### View Sales (with Authorization)
```bash
curl https://api-gateway-url/view-sales \
  -H "Authorization: Bearer {jwt-token}"
```

### Get Driver Information
```bash
# Get driver details
curl https://api-gateway-url/driver?driver_id=DRV001
```

### Get Truck Information
```bash
# Get truck details
curl https://api-gateway-url/truck?truck_id=TRK001
```

## Schema Validation

All schemas follow these standards:
- **OpenAPI 3.0.3** for REST API specifications
- **JSON Schema Draft 7** for Lambda function schemas
- **Comprehensive Examples** for all request/response formats
- **Error Handling** specifications for all failure cases

## Security Considerations

1. **Private S3 Access**: Schemas are stored in a private bucket with no public access
2. **Presigned URLs**: Access via time-limited presigned URLs (1 hour expiration)
3. **No Sensitive Data**: Schemas contain only structural information, no credentials
4. **CORS Configuration**: Allows cross-origin access for web-based agents
5. **IAM-Based Security**: Lambda functions use IAM roles for secure S3 access
6. **Authorization Patterns**: Documented in Lambda schemas for proper implementation

## Workshop Learning Objectives

These schemas support the workshop's core learning goals:
- **Federated Authentication**: Multi-tenant identity patterns
- **Delegated Authorization**: Role-based access control
- **Secure MCP Integration**: Structured tool interfaces for AI agents
- **Comprehensive Auditing**: Logging patterns for agentic AI operations

## Troubleshooting

### Schema Upload Issues
1. Verify CloudFormation stack is deployed successfully
2. Check IAM permissions for S3 bucket access
3. Ensure AWS CLI is configured with proper credentials

### AgentCore Integration Issues
1. Verify S3 URLs are accessible via browser
2. Check CORS configuration if accessing from web applications
3. Validate schema format using online JSON Schema validators

### API Testing Issues
1. Replace `{api-gateway-url}` with actual API Gateway endpoints
2. Ensure proper authentication tokens for protected endpoints
3. Check CloudWatch logs for Lambda function errors

For additional support, refer to the main workshop documentation.
